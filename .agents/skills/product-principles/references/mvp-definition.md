# MVP Scoping Reference

Use this reference when validated candidates compete for the first delivery scope.

## Decision

1. Define the smallest observable outcome to deliver or validate.
2. Gather candidates supported by that outcome, an accepted boundary, or decision-relevant evidence.
3. Reuse or simplify existing behavior before adding new surface.
4. Compare candidates only when the outcome cannot determine inclusion directly.
5. Select the smallest set that delivers the outcome within its feasibility boundary.
6. Record later work only for a named roadmap consumer.

## Comparison Methods

| Method | Use when |
|--------|----------|
| MoSCoW | The consumer needs explicit inclusion and exclusion categories |
| RICE | Reach, impact, confidence, and effort evidence exists and changes priority |
| ICE | A lightweight relative comparison is sufficient |

The framework supports the decision; it creates no obligation to score candidates already excluded by scope.

## Scope Reduction

- Remove a candidate that does not contribute to the core outcome.
- Narrow the user segment or use case when it preserves observable value.
- Use a manual or simulated path when automation is not part of the current validation.
- Defer quality or scale work whose effect is outside the current outcome, boundary, or proof.

Use product-principles confidence and material-risk rules to judge readiness; a fixed release label or feature count does not determine MVP scope.
